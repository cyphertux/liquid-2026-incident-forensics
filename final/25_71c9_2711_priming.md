## 4. Cache-key algorithm (vulnerable era)

Source: pre-fix `SignatureCache::ComputeEntryRangeProof`  
(`final/patches/sigcache_pre_fix_verify.cpp`, `final/01_code_history.md`).

```cpp
// PRE-FIX (also elements-23.3.3):
CSHA256 hasher = m_salted_hasher_range_proof;
hasher.Write(proof.data(), proof.size())
      .Write(commitment.data(), commitment.size())
      .Finalize(entry.begin());
```

| Included in OLD key | Not included |
|---|---|
| rangeproof bytes | asset / generator |
| value commitment bytes | scriptPubKey / extra_commit |
| process salt (`m_salted_hasher_range_proof`) | nonce field |

**Consequence (FACT):** two verifies collide in-cache iff they share **identical** `(proof, value_commitment)` byte strings (same process salt).

Post-fix (`c26d719…`) also hashes asset + script — irrelevant to whether 71c9/2711 match f24a under OLD key (they already mismatch on proof/commitment).

## 6. Cryptographic proof (why priming is impossible via these txs)

Call site (Elements): `VerifyRangeProof(voutwit.rangeproof, vout.value_commitment, asset, scriptPubKey)`.

For 71c9/2711 out0:

- `rangeproof` = P' ≠ P1  
- `value_commitment` = C' ≠ C1  
- `scriptPubKey` **contains** C1 as data push — but script is **not** in the OLD key and is **not** substituted for the commitment argument.

Therefore a successful mempool verify of 71c9/2711 inserts at most `H(salt\|\|P'\|\|C')`, never `H(salt\|\|P1\|\|C1)`.

**Classification: NOT PRIMING OF P1/C1.**
